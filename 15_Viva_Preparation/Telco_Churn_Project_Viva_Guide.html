1. The project story — explain it first

What problem are we solving?

A telecommunications company loses income when customers stop using its services. It cannot call every customer or give everyone a discount. The project helps the retention team prioritise: it estimates each customer's chance of leaving (churning), then places customers from highest risk to lowest risk.

What is churn?

Churn means a customer leaves the company. In this project, the target column is Churn, with two possible values: Yes or No.

What is the machine-learning task?

It is binary classification. “Binary” means there are two outcomes: churn or no churn. The model produces a probability, such as 0.72 (72% estimated risk), rather than only a Yes/No label. This is useful because a manager can choose how many people to contact.

“Our project is a customer churn prediction system for a telecom company. The main purpose is not to make decisions automatically. It is to help the retention team contact the highest-risk customers first and test suitable offers.”

2. Dataset and key findings

What data did we use?

We used the public IBM Telco Customer Churn dataset. It contains 7,043 customer records and 21 columns. One row represents one customer at one point in time. It is a public sample, not a real company’s live data.

Important data-quality checks

  • There were no duplicate rows and no duplicate customer IDs.
  • TotalCharges was stored as text, although it should be a number.
  • It had 11 blank values. All were customers with tenure = 0, meaning they were new and had not yet been billed. We changed these blanks to 0.
  • We removed customerID because an ID is only a label; it should not determine churn risk.
Good viva wording: “We did not simply fill missing values without checking. We found that all 11 blank TotalCharges records belonged to customers with zero months of tenure. Therefore, zero was a sensible value because no billing time had passed.”

4. Preparation and feature engineering

Why did we encode categorical values?

Models cannot directly calculate with words such as “Month-to-month” or “Fibre optic.” We used one-hot encoding: it creates a simple 0/1 indicator for each category. For example, a customer can have Contract_Month-to-month = 1 and the other contract indicators = 0. We used handle_unknown=ignore, so an unexpected category in later data does not crash the system.

Why did we scale numerical values?

Scaling puts numbers like tenure and monthly charge onto a comparable range. It was applied only to models that are sensitive to scale, such as Logistic Regression. Tree-based models do not require it because they split values using cut-off points.

What features did we test?

ChoiceDecisionReason
Number of add-onsKeptIt added useful predictive information.
Automatic paymentTested, not retained as a special engineered featureIt did not add enough beyond the existing payment data.
Expected-versus-observed charges gapTested, not retainedIt did not improve the main metric enough.
GenderRemovedIt did not add measurable predictive value, so keeping it was unnecessary.
Class weightingTested, not usedIt did not improve our primary metric, PR-AUC.
Why test and remove features? More features are not automatically better. Unhelpful fields can add noise, complexity, privacy concerns, or unfairness risk. We kept only changes that had evidence of value.

5. Models: what we tried and why Logistic Regression won

The candidates

ModelWhat it does simplyWhy includedInitial PR-AUC
Dummy classifierAlways predicts the most common class: no churn.Sets the minimum benchmark; any useful model must beat it.0.265
Logistic RegressionCombines input signals to estimate a probability of churn.Simple, fast, stable, and easier to explain.0.661
Decision TreeUses a sequence of if/then questions.Easy to visualise, can capture simple non-linear patterns.0.613
Random ForestCombines many decision trees.Can capture more complex relationships and reduce dependence on one tree.0.658
HistGradientBoostingBuilds many small trees in sequence, each improving earlier errors.A strong modern tree-based comparison model.0.644

How did we compare them fairly?

All candidates used the same training data, preprocessing logic, and five-fold stratified cross-validation. We then tuned the four real models using RandomizedSearchCV inside nested cross-validation. Random search tries a sensible sample of settings rather than every possible combination; this is more efficient than an exhaustive grid when there are many settings.

Why not choose the highest-scoring Random Forest?

After tuning, Random Forest had the highest nested cross-validation PR-AUC: 0.664 ± 0.019. Logistic Regression scored 0.661 ± 0.019. The difference was very small and within one standard error, meaning the observed advantage was not strong enough to justify the extra complexity. Our pre-defined rule was to choose the simplest model that performs comparably. Therefore, we selected Logistic Regression, tuned with C = 4.5706.

Strong evaluator answer:
“We did not choose Logistic Regression because it had the absolute highest score. Random Forest was slightly higher, but the difference was within normal variation. Since Logistic Regression was statistically comparable, easier to explain, faster to maintain, and sufficient for the business goal, it was the more responsible choice.”

What does C = 4.5706 mean?

C controls how strongly Logistic Regression limits overly large influence from individual inputs. It is selected during tuning. You do not need to call it “the best number”; say it is the value that performed best among the values tested within the training process.

6. Evaluation: prove the model is useful

Why did we not use accuracy as the main measure?

Only 26.5% of customers churned. A useless model that predicts “no churn” for every customer would still be about 73.5% accurate. It would miss every churner. Therefore, accuracy would give a misleadingly good picture.

MeasurePlain meaningOur test resultWhy it matters
ROC-AUCHow well the model ranks a random churner above a random non-churner across all thresholds. 0.5 is random; 1.0 is perfect.0.842Shows strong overall ranking ability.
PR-AUCHow well the model balances finding churners with avoiding too many wrong alerts.0.631More informative than accuracy when churners are the smaller group. Baseline is 0.265.
F1 at 0.50A balance of precision and recall at the usual 0.50 cut-off.0.607A reference result, not necessarily the best business policy.
Brier scoreHow close predicted probabilities are to actual outcomes; lower is better.0.138Checks whether risk probabilities are reasonably sensible.

Precision and recall without confusion

  • Precision: Of customers we flagged, what percentage truly churned? High precision means fewer unnecessary contacts.
  • Recall: Of customers who truly churned, what percentage did we flag? High recall means we miss fewer likely churners.
  • Trade-off: Lowering the threshold flags more people. Recall rises, but precision normally falls.

Why is the selected threshold only 0.07?

A threshold is the action cut-off. At 0.50, we would contact only customers whose estimated risk is at least 50%. But a 50% cut-off is not a business law. We chose 0.07 using out-of-fold training predictions and explicit campaign assumptions:

  • Offer cost = 20 per contacted customer.
  • 30% of contacted churners can be saved.
  • The value of saving a customer = 12 months of that customer's monthly charge.

Under those assumptions, 0.07 had the highest expected net benefit. On the untouched test set, it produced 37.9% precision, 97.3% recall, and flagged 68.1% of customers. This is deliberately broad: it is appropriate only when contact is low-risk and the stated assumptions are believable.

Never overclaim: The threshold is not “universally best.” It is best only under our assumed offer cost, save rate, and retained value. If the company has limited capacity, we recommend a narrower top-risk list.

Capacity-based option: top 20%

If staff can contact only 20% of the test customers, they would contact 282 people, reach 187 observed churners, and have 66.3% precision. This is often easier to use operationally than a fixed probability threshold.

7. High-risk profile, recommendation, and responsible use

What did the flagged group look like?

Characteristic at threshold 0.07Flagged customersNot flagged
Observed churn rate37.9%2.2%
Median tenure16 months57 months
Month-to-month contract78.1%5.1%
Fibre-optic service58.5%11.4%

Permutation importance also identified tenure, internet service, monthly charges, and contract as the strongest predictors. This tells us what the model relies on for prediction. It does not prove that changing one of these causes a customer to stay.

Business recommendation

  1. Use the score to prioritise outreach, starting with a capacity-appropriate group such as top 10% or top 20%.
  2. Review service and price experience for higher-risk fibre-optic customers.
  3. Engage newer customers early, especially those on flexible contracts.
  4. Offer contract or payment-method changes only when they fit the customer’s needs.
  5. Run an A/B test before large-scale rollout: compare contacted high-risk customers with similar high-risk customers who are not contacted.

Why is the A/B test essential?

Our model predicts who may leave. It does not prove that a discount, call, or contract change will stop them from leaving. An A/B test measures the extra retention caused by the offer, rather than confusing the offer’s effect with normal customer behaviour.

Ethics and fairness

  • The model should support a staff member, not make automatic harmful decisions.
  • It must never be used to deny service or penalise customers.
  • Gender was removed because it did not improve performance.
  • SeniorCitizen is age-related and needs monitoring. In the test set, 85.6% of senior customers were flagged versus 64.9% of non-senior customers. This may be a real risk difference, a data issue, or unfairness; the senior group was relatively small (222 customers).
  • Monitor flag rate, recall, false-positive rate, and actual offer outcomes for relevant groups using real operating data.
  • Customers should receive clear offers and be able to decline communication.

Limitations you must state openly

  • The IBM data is a public sample, not a real telecom company’s current data.
  • There are no dates and the churn time window is unclear, so we cannot track changing risk over time.
  • The dataset has no real customer lifetime value, offer response, complaint, competitor, or service-quality information.
  • Expected money results are scenario estimates based on assumptions, not observed business profit.
  • Relationships in the data are associations, not causes.
  • Performance can change on new data, so the model needs monitoring and retraining with real data.

8. A confident viva speaking plan

Your 90-second full overview

“Our project addresses customer churn in a telecom company. Churn means a customer stops using the service. The retention team has limited time and cannot contact everyone, so our goal was to estimate each customer’s likelihood of leaving and rank customers by risk.

We used the IBM Telco dataset with 7,043 customers and 21 columns. We checked data quality, converted TotalCharges from text to numbers, and handled 11 blank values after confirming they belonged to new customers with zero tenure. We split the data into 80% training and 20% test data before preprocessing, so the final test result would be fair.

We compared Logistic Regression, Decision Tree, Random Forest, and HistGradientBoosting using cross-validation. Random Forest had a very slightly higher score, but Logistic Regression was within the same performance range and was simpler to explain and maintain, so we selected it. On the untouched test set it achieved ROC-AUC of 0.842 and PR-AUC of 0.631.

Finally, we used the scores to support retention campaigns. A low threshold of 0.07 maximised expected value under our stated assumptions, while a top-20% list is more practical when capacity is limited. The model is decision support only, and any offer must be validated with an A/B test.”

Decision Say what you chose. Reason Say the evidence or business need. Trade-off Show that you understand the limitation.

Example: “We chose PR-AUC as a main metric because churners are the smaller group. Accuracy could look high even if we missed all churners. The trade-off is that PR-AUC is less familiar, so we also reported ROC-AUC, precision, recall, F1, and calibration.”

Short rules for a strong answer

  • Start with the conclusion, then explain it.
  • Say “in this dataset” rather than claiming it is true everywhere.
  • Say “associated with” rather than “caused by.”
  • Do not hide limitations; explaining them shows maturity.
  • If challenged about a number, explain what it means before giving it.

9. Evaluator questions with clear answers

Practise these as conversations, not a speech. The answers use simple English intentionally.

1. What is the main aim of your project?
To help a telecom retention team identify and rank customers who are more likely to leave, so the team can focus contact and offers where they may matter most.
2. Why is this a classification problem and not a regression problem?
The final outcome has two classes: churn or no churn. We predict the chance of the churn class. Regression is normally used when the answer is a continuous number, such as a price.
3. Why predict a probability instead of only Yes or No?
A probability lets the company rank customers. If it can contact only 20%, it can start with the highest scores. A simple Yes/No label does not give that flexibility.
4. What was the data issue with TotalCharges, and how did you handle it?
It was stored as text and had 11 blank values. We checked those records and found every one had zero tenure, so they were new customers with no charges yet. We converted the column to numeric and used zero for those records.
5. Why remove customerID?
It is an identifier, not a meaningful customer behaviour. Keeping it can make a model learn accidental patterns that will not work for future customers.
6. What is data leakage? How did you prevent it?
Leakage happens when information from the test data or future information influences training. It makes results unrealistically good. We split first, kept the test set untouched, and put transformations inside a pipeline so each training fold learned only from its own training data.
7. Why use a stratified 80/20 split?
Because only 26.5% churned. Stratification keeps a similar churn percentage in both sets. The 80/20 split leaves enough data to learn while reserving 1,409 customers for an unbiased final test.
8. What is one-hot encoding and why did you need it?
It changes category words into 0/1 columns that a model can use. For example, a month-to-month contract becomes an indicator. We needed it because models cannot calculate directly with text labels.
9. Why did you scale numerical data?
Logistic Regression is affected by very different number ranges. Scaling helps it treat numerical inputs consistently. Tree models do not need scaling, so we did it only where useful.
10. Why did you use a pipeline?
A pipeline keeps preparation and modelling together. It applies the same steps in the right order to training data, validation folds, and future predictions. Most importantly, it reduces leakage.
11. Why did you compare several models?
There is no reason to assume one model is best before testing. Logistic Regression is simple, while tree-based models can learn more complex patterns. Comparing them gives evidence for our final choice.
12. Why was Logistic Regression selected instead of Random Forest?
Random Forest had the highest nested cross-validation PR-AUC, 0.664, but Logistic Regression was 0.661 and within one standard error. Since the difference was tiny, we chose the simpler, more explainable model. It gave strong test results without unnecessary complexity.
13. Why did you use cross-validation?
A single validation split can be lucky or unlucky. Five-fold cross-validation repeats the check across different parts of the training data, so the comparison is more reliable.
14. What is nested cross-validation?
It separates model-setting selection from performance checking. The inner process selects settings, while the outer process checks them on unseen training folds. This gives a fairer estimate for tuned models.
15. Why is accuracy not your main metric?
Because most customers did not churn. A model that says “no churn” to everyone would be 73.5% accurate but would find no churners. We used PR-AUC and ROC-AUC, then checked precision and recall for the campaign decision.
16. Explain ROC-AUC of 0.842 in simple terms.
It means the model is good at ranking churners above non-churners across many possible cut-offs. It is much better than random ranking, which would be 0.5. It is not 84.2% accuracy.
17. Explain PR-AUC of 0.631 in simple terms.
It measures how well the model finds churners while avoiding too many wrong alerts. Our starting churn rate was 0.265, so 0.631 shows a meaningful improvement over the no-skill baseline.
18. Why is your threshold 0.07 rather than 0.50?
0.50 is only a common default, not a business rule. We selected 0.07 because it gave the highest expected benefit using our stated offer cost, save rate, and customer value assumptions. It is a broad policy with high recall, so it must be changed if those assumptions or campaign capacity change.
19. What happens when you lower the threshold?
We flag more customers. This helps us find more actual churners, so recall rises, but it also creates more false alerts, so precision usually falls.
20. What does the top-20% policy mean?
We sort customers by predicted risk and contact only the highest 20%. In the test set that was 282 customers, and 187 of them actually churned, giving 66.3% precision. It is useful when the campaign has limited capacity.
21. Which factors were most important?
Tenure, internet service, monthly charges, and contract were strongest. High-risk customers were often newer and on month-to-month contracts. These are prediction patterns, not proof that one factor causes churn.
22. Can you say fibre optic causes churn?
No. The data shows an association only. There may be other reasons, such as price, experience, or customer type. To test causes, we need controlled experiments or stronger causal research.
23. How would you improve the project with real company data?
I would add dates, customer contact history, complaints, service quality, offer response, real retention value, and real campaign cost. I would validate over time, monitor performance and fairness, and run A/B tests for offers.
24. What are the ethical risks?
The model can make unnecessary contact more likely for some people and may treat groups differently. It should never deny service or make a harmful automatic decision. We removed gender because it added no value and would monitor outcomes by relevant groups, especially the age-related senior-citizen field.
25. What is the biggest limitation of your business-value result?
The money result is based on assumptions: offer cost of 20, 30% save rate, and 12 months of monthly charges as value. It is a planning scenario, not observed profit. A real company must replace those assumptions with measured results.
26. If your test performance drops after deployment, what would you do?
First check data quality and whether customer behaviour has changed. Then compare current results with the original baseline, review fairness, recalibrate the threshold, and retrain only after using recent labelled data and validating it properly.
